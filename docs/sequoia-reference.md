# macOS Sequoia 15 Launchpad 视觉基准

研究及实现核对日期：2026-09-22。用户指定 Sequoia 15；不能把 OS X Lion 的分裂式文件夹与最后一代 Launchpad 混为一谈。本记录分别列出原始图像量测、推定规则、当前实现与验证结果，不把本项目现有实现当作原版证据。第一轮交互修复历史见 [旧版 Launchpad 交互修复记录](classic-launchpad-interactions.md)。

后续针对内存、选中白框与排序跳动的实现和实测见 [内存与排序优化记录](memory-and-reorder.md)。该轮保留键盘选中提示，移除粗白描边及鼠标打开文件夹后残留的选择，并为减少动画模式加入短促、无回弹的排序反馈。

## 文件夹标题和慢速拖入修复

本轮处理用户反馈的两个回归。Apple 的 [Sequoia 15 指南](https://support.apple.com/en-euro/guide/mac-help/mh35840/15.0/mac/15.0) 明确描述打开文件夹后点击名称修改，以及拖入、拖出 app；没有公布悬停或退出的精确时间阈值。

- **标题点击关闭文件夹**：原生窗口复现确认，标题由面板 overlay 向上偏移绘制，但命中仍受面板矩形限制；点击实际文字触发了下层背景关闭。标题现作为独立同级视图定位，保留原来的字体和位置，使用真实 Button 进入原位文本编辑。Return 保存、Escape 放弃本次修改；失焦或关闭文件夹时保存非空名称。无障碍树在编辑时暴露文本框，空闲时暴露带当前名称的重命名按钮。
- **慢速拖入后自动退出**：悬停展开使面板远离根图标，原逻辑立即将尚在根图标位置的指针判成拖出，0.20 秒后关闭面板。现按文件夹记录是否已进入：外部拖入必须先进入展开面板，之后离开才启动退出计时；从已有文件夹内部提起则立即允许拖出。展开、关闭、取消时清理旧坐标和状态。展开与悬停不改变成员关系，仍在有效落位后提交顺序。

`FolderDragEntryTests` 新增六组确定性回归：悬停后等待 60 秒再进入并插入指定位置；进入、离开及中途返回；从已打开文件夹直接拖出；取消后重新展开及旧坐标；跨文件夹慢速进入；离开后重新进入来源文件夹。测试同时核对内存模型与已保存布局在落位前不被修改。完整回归 **102/102 通过**。

隔离调试副本的原生 GUI 已验证标题实际坐标单击、全选粘贴中文名称后 Return 保存、Escape 放弃修改且文件夹保持打开、点击背景保存后重新打开、根 app 拖入 Utilities、再从文件夹拖回根网格第一行第三位。测试后恢复调试副本名称与顺序。中文通过粘贴验证，不代表系统输入法候选流程；GUI 工具不能分段按住鼠标等待，60 秒慢速悬停由实际拖拽状态机的可控时间测试验证。Universal 2 构建及严格签名检查通过。

## 文件夹的重要结论

Sequoia 高分辨率原图中，文件夹是接近全宽、浅色半透明、大圆角的面板。标题在面板外上方居中。打开后，根图标、搜索框和 Dock 全部隐藏；背景保留模糊壁纸。没有顶端尖角、根图标上下分裂、局部锚定的小气泡、面板内工具栏或 app 数量标题。30 个项目排成 7 列、5 行，最后一行从左边开始。

MacMost 2023 视频 5:54 的 3 项文件夹验证：面板仍近全宽；只有一行；三个 app 占用网格的第 1、2、3 列并靠左排列；面板在屏幕纵向中部，标题位于面板外上方。将相同规则用于 Sequoia 小文件夹是有相邻版本依据的推断，目前没有 Sequoia 1–7 项文件夹原图或实机逐帧验证。

Apple Sequoia 官方根图的 Games 文件夹只有 Chess 一个缩略图，证明系统可存在单项文件夹。但普通用户文件夹从 2 项减为 1 项时是否自动解散，不能仅凭 Games 推论。[2011 年原作者 Lion 实测](https://gilsmethod.com/how-to-create-rename-and-delete-app-folders-in-mac-os-lion) 明确描述剩一项会解散，恰好说明跨版本规则不能直接沿用。当前项目对普通文件夹仍保留早期实现：移出后剩一项就解散，并在来源位置保留该 app。没有取得该规则在 Sequoia 上的直接证据，故不把它列为已完成的原版一致性验证。

## 原版行为证据

Apple Sequoia 文档直接确认：方向键逐项导航；Command+左右换页；Return 打开所选文件夹；Escape 关闭文件夹；同页排序、边缘跨页、拖动建文件夹及拖入拖出；点击标题重命名；长按进入抖动与可卸载项的 Delete 按钮；app 可以从 Launchpad 拖到 Dock。

MacMost 的实际演示还显示：按住 Option 临时进入抖动；搜索自动选中首项；直接从搜索结果开始拖动，随即恢复搜索前的页面，再将 app 放置到该页。项目此前全面禁用搜索态拖动，这一遗漏现已补齐。不过视频来自 2023 年，其细节仍应在 Sequoia 实机进一步确认。

卸载的确认对话框文字、抖动幅度与周期、开合动画曲线、悬停阈值、拖出后重新进入文件夹的完整状态机，公开静态截图不能证明。将可见静态几何与动画/状态机的实机验证分别记录，不以测试通过代替像素或逐帧对照。

第三处前后有章节剪辑，未分别观察到点击清除按钮与按 Escape 的完整动作，因此只能确认“编辑中的空框”确实存在，不能用这一帧证明两种清空操作的完整焦点规则。点击空框时的精确左移动画也尚未在 Sequoia 原版上逐帧核实。

Apple 的旧 `centersPlaceholder` 行为说明将居中限定为“空且无焦点”，获得焦点时向边缘移动；这一概念可帮助划分状态，但 API 本身已无效。本次修复采用显式的三种显示状态：空闲空框居中且无光标；点击空框后显示左侧提示与原生光标；直接打字或继续输入后显示左侧文字，并只在非空时显示清除按钮。

为保持连续输入，本项目选择让清除按钮及 Escape 清除非空搜索后保留编辑状态，显示左侧提示与光标；这属于本次实现规则，尚未分别取得两种操作的 Sequoia 原版实证。打开文件夹、显示对话框、隐藏启动器或开始拖动时结束搜索编辑；空内容恢复空闲居中状态。原生 field editor 承接字符输入、插入点移动及输入法组合事件，不通过逐字符拼接模拟文本输入。编辑中的空提示由 SwiftUI 在左侧绘制，以补足本次 GUI 中发现的原生占位文字未显示问题；窗口另行转发 Command+A/C/V/X/Z 与 Command+Shift+Z 到原生编辑操作，以支持没有标准 Edit 菜单的启动器窗口。

首轮搜索修复的 `./run-quality-tests.sh` **87/87 通过**。新增的四组相关测试只检查键盘事件分类，不能称为实际输入法候选、组合、确认及取消流程的端到端验证。首轮原生 GUI 已验证直接按 `t` 再输入 `erminal`、清除按钮保留焦点、按 Down 后重新点击搜索框并将插入点左移输入 `x` 得到 `terminaxl`、Escape 清空后继续编辑、打开并关闭文件夹后恢复空闲居中，以及空闲态 Command+V 开始搜索。

首轮 GUI 同时发现编辑中的原生占位文字未显示，以及没有 Edit 菜单导致编辑态 Command+A/V 无响应；左侧提示与编辑快捷键转发已修正。最终 Universal 2 生产构建已完成，确认包含 x86_64 与 arm64，`codesign --verify --deep --strict` 通过。原生 GUI 复验通过以下场景，调试副本已退出：

- 编辑态粘贴 `測試` 正常显示中文，再按 Command+A 粘贴 `Terminal`，内容完整替换。Command+Z 可撤销全选删除并恢复 `Terminal`，Command+Shift+Z 可重做删除。

## 当前已落地实现

默认根网格采用 7 列、5 行；1440×900 pt 基准下，NSImage 画布为 90 pt、列距 180 pt、行距 138 pt。90 pt 指完整图标画布，不能与截图中约 71 pt 的可见主体混淆。较小窗口和用户自定义图标大小会触发布局调整，不强行在不足的空间内放入 35 个项目。空行保留原有网格位置。

搜索框为 250×25 pt，3 pt 圆角；原先距物理屏幕顶部固定 25 pt，本次改为距硬件安全内容区顶部 25 pt，验证状态见下节。分页圆点直径 6 pt，仅在多页时显示。设置入口移至右上角悬停区域，也可用 Command+, 打开，以免改变搜索框中心。设置入口是本项目的扩展功能。

文件夹使用近全宽浅色面板、40 pt 连续圆角与面板外的 28 pt 轻字重标题。稀疏文件夹保留根网格列位，项目靠左排列，按所需行数增加高度，最多五行后分页；一行文件夹纵向居中。打开时隐藏根网格、搜索、根页点和 Dock；关闭后恢复。闭合文件夹图标的浅色主体为图标画布的 0.8 倍，编辑时删除按钮对齐可见图标左上角。已删除早期上下分裂根图标的视觉处理。

长按进入持续编辑，Option 控制临时编辑。普通模式显示图标抖动与可卸载项的删除按钮，减少动画模式停止持续抖动。方向键选择项目，Return 打开 app 或文件夹，Command+左右换页；搜索自动选择首项。Escape 依次取消拖拽、退出编辑、清搜索、关文件夹、关闭启动器，并为重命名、输入法组合文字和对话框保留各自的按键行为。

搜索结果可直接拖出，拖起后恢复搜索前的根页面。文件夹成员关系到有效落位才提交，因此取消不会提前把 app 移出文件夹。来自文件夹的项目仍能在根页前后插入、跨页或进入其他文件夹。原生 app 拖拽先注册 NSURL，再注册内部标识 NSString，以同时正确传递真实文件 URL 和内部排序标识；Dock 接收这一数据的端到端行为尚未实际验证。

减少动画模式下，根分页与文件夹分页只挂载当前页，旧页立即移除，仅新页淡入；落位处理检查页归属。这项修正针对 GUI 调试中观察到的透明相邻页接收原生 drop、将项目误投到后一页的问题。安全区调整前的构建已通过下列指定操作的原生拖拽复验。

商店 app 可在删除确认后移到废纸篓，支持符合识别规则的 Mac App Store app 及 Apple silicon 上的 iOS app 封装。操作前会重新检查应用位置、商店收据或受支持封装元数据以及运行状态；正在运行或资格发生变化的应用会报告失败。只有成功后才从当前模型移除，并重新扫描；失败保留现有项目。该流程使用可恢复的废纸篓处理，不额外删除用户数据，也不声称与原版所有版本的底层卸载机制相同。
