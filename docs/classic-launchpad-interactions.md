# 旧版 Launchpad 交互修复记录

研究日期：2026-09-22。本文最初记录“减少动画”和文件夹拖出排序的第一轮修复，当时尚未确定单一视觉版本。用户随后明确指定 macOS Sequoia 15；当前视觉基准、截图量测、已落地功能与最新验证记录以 [Sequoia 15 视觉基准](sequoia-reference.md) 为准。

本页保留交互修复的背景，并同步当前行为。早期的自适应多列网格、背景行分裂式文件夹以及“完整键盘导航未实现”的描述已经失效；不能将第一轮 49 项测试或旧版构建记录当作当前版本的完整验证。

## 一手资料与证据边界

- [Apple：macOS Sequoia 15 的 Launchpad 用户指南](https://support.apple.com/en-euro/guide/mac-help/mh35840/15.0/mac/15.0)：确认同页拖动排序、屏幕边缘跨页、拖动创建和加入文件夹、从文件夹拖出、点名称重命名，以及方向键选择、Command 左右翻页、Return 打开文件夹、Escape 关闭文件夹。
- [Apple：Mac mini / macOS 15 的 Launchpad 说明](https://support.apple.com/en-ie/guide/mac-mini/aside/apd2d2a58738/2024/mac/15)：交叉确认搜索、网格排序、文件夹拖入拖出及分页方式。
- [Apple Developer：Reduced Motion 评估准则](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/reduced-motion-evaluation-criteria)：避免大幅度缩放、深度和持续运动；具有信息意义的状态切换可以采用淡化、强调或颜色变化，不应机械删除全部反馈。
- [Apple Developer：NSWorkspace.accessibilityDisplayShouldReduceMotion](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducemotion)：读取系统偏好，并通过 NSWorkspace 的通知中心接收辅助功能显示选项变化。

Apple 用户指南描述可见行为，没有公开 Launchpad 的弹簧曲线、逐帧实现或精确悬停时间。动画长度、拖出容差、停留阈值及 Escape 的完整优先级均为本项目的实现选择。后续研究加入了实际系统截图和原作者视频；静态量测与动画推定的区别详见 Sequoia 基准文档。

## 已保留和补齐的交互

### 减少动画

根分页和文件夹分页使用同一短淡化策略。当前页与显示页立即更新，去掉先隐藏整页、再通过延迟计时器交换内容的流程，避免快速翻页、搜索和页数变更互相覆盖。

后续原生拖拽调试发现：减少动画模式下，透明的相邻页仍可能接收 drop，导致项目误投到后一页。根分页与文件夹分页现只挂载当前页，旧页立即移除，仅新页淡入，并在落位处理时检查页面归属。最终构建已通过同页排序、搜索结果拖回原页、文件夹拖出后插入指定位置的 GUI 复验。

启用减少动画时，页面不再大幅水平位移，拖拽预览变化不使用弹簧移动，图标消失不放大，编辑模式停止持续抖动。打开和关闭界面保留短淡化。系统偏好变化会更新模型中的减少动画和减少透明度状态。当前文件夹在所有动画模式下都采用 Sequoia 风格独立面板，背景网格不再分裂。

### 文件夹拖出与排序

拖动图标越过文件夹区域并短暂停留后，收起文件夹，继续同一次原生拖拽。此时仍保留文件夹成员关系和已保存顺序；只有有效落点提交后才真正移出。因此，取消或落在无效区域不会预先拆散文件夹。

根页面接受来自文件夹的 app，支持放在目标图标之前、之后或网格位置，也可以继续跨页、加入其他文件夹或与另一个 app 组成新文件夹。移动后只剩一个 app 的普通来源文件夹仍沿用早期实现：展开成该 app，并保留来源位置。尚未取得 Sequoia 普通文件夹 2→1 的直接证据，该行为不作为“已证实与原版一致”的结论。

根页面空白区域根据松手坐标重新计算插入位置，避免原生拖拽结束事件与跟踪计时器的先后顺序使落点退回末尾。预览状态只在目标变化时发布，减少静止拖拽时重复刷新网格。

### 搜索与快捷键

- 打开启动器时聚焦搜索；打开文件夹时移走搜索焦点。
- 方向键在当前根页面、文件夹或搜索结果中建立并移动选择；Return 启动所选 app 或打开所选文件夹。搜索默认选中首项。
- 搜索结果可直接拖动；拖起后清除筛选并回到搜索前的根页面，在实际落位前不改变来源文件夹成员关系。
- Escape 依次处理拖拽、编辑模式、搜索、文件夹、启动器；对话框和文本编辑仍优先使用各自的按键行为。
- Command 左右键控制当前根页面或文件夹分页；文件夹名称编辑、输入法组合文字、设置及对话框期间保留文本或对话框原有按键行为。

点按文件夹名称直接编辑、页码圆点、悬停展开已有文件夹和边缘翻页沿用现有实现。

### 编辑与商店 app 卸载

长按进入持续编辑模式；按住 Option 临时编辑，松开后退出临时状态。可卸载的商店 app 显示删除按钮，包含受支持的 Apple silicon iOS app 封装。点击后先显示确认界面；确认才移动到废纸篓。执行前重新检查资格与路径，并拒绝删除正在运行的 app；失败时保留列表中的应用并显示错误。

废纸篓处理是本项目有意保留的可恢复实现，不声称等同于原版 Launchpad 所有版本的底层卸载方式。用户数据不会随此操作额外清理。

## 验证与范围

当前 `./run-quality-tests.sh`：**78/78 通过**，包括新增的 3 项拖拽载荷测试。覆盖网格几何、编辑与键盘状态、搜索拖出返回原页、文件夹成员提交、拖拽载荷、卸载资格及路径检查等回归。最终 Universal 2 构建及 `codesign --verify` 检查通过。

最终调试副本的原生 GUI 复验包括：搜索 Terminal 后拖起，恢复第二页并插入第一行第三位；根页面同页排序；从 Utilities 拖出 Archive Utility 并插入第一页第一行第三位。商店 iOS 封装 app 的删除确认框取消后，应用仍保留；Escape 可退出编辑，Command+, 可打开设置。文件夹图标已调整为画布的 0.8 倍浅色外观，删除按钮位于可见图标左上角。没有对用户真实 app 执行卸载；调试副本已退出。

模型测试不能证明 AppKit 原生拖拽时序、SwiftUI 命中区域、全部动画帧率或原版 Sequoia 的逐像素一致性。原生 app 拖拽现在先注册 NSURL，再注册内部标识 NSString，以同时保留正确的真实文件 URL 与内部排序标识，供 Dock 等外部目标使用；尚未完成 Dock 端到端接受验证。系统入口、全局多指手势和游戏手柄导航也不在本次完成范围。

- 使用独立 bundle identifier 的调试副本进行原生窗口验证，避免改动正式版的文件夹和排序。
- 在减少动画模式下验证：直接输入搜索、Escape 清除搜索后仍停留启动器、Command 左右翻页、连续翻页后立即搜索、Return 启动计算机。

- GUI 工具的拖动接口不能分段按住并逐帧采样；长时间悬停后继续跨页、取消以及源文件夹解散等由模型测试覆盖。未进行实际 FPS/帧时间量测，也未宣称全部原版交互已复刻。
